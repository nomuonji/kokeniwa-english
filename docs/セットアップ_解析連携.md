# Search Console / GA4 の連携

サイトの検索流入とアクセスを計測し、そのレポートを Claude Code からも読めるようにする。
目的は「どの記事がどのクエリで拾われているか」を見て、記事の改稿と新規テーマ選定に使うこと。

- 計測タグの埋め込み: `site_config.json` の `analytics` → `site/templates/layout.py` の `_analytics_html()`
- レポート取得: `scripts/fetch_seo.py` → `reports/latest.md`（git管理外）
- 認証: Google サービスアカウント（鍵は `.secrets/google-sa.json`、git管理外）

---

## 1. Search Console にサイトを登録

1. https://search.google.com/search-console を開く（youfree731@gmail.com でログイン）
2. 「プロパティを追加」→ **ドメイン** を選び `kokeniwa.net` を入力
   - ドメイン単位なので `en.` と `ja.` の両方をまとめてカバーできる。おすすめ。
3. 表示された TXT レコードを Cloudflare のDNSに追加
   - Cloudflare ダッシュボード → kokeniwa.net → DNS → レコードを追加
   - タイプ `TXT` / 名前 `@` / 内容 `google-site-verification=...`
4. Search Console に戻って「確認」

> DNSを触りたくない場合は「URLプレフィックス」で `https://en.kokeniwa.net/` を登録し、
> HTMLタグ方式の `content="..."` の値を `site_config.json` の
> `analytics.google_site_verification` に入れてビルド・プッシュしてから確認する。

### サイト別のプロパティも作る

ドメインプロパティは `en.` と `ja.` のデータが合算されるため、レポートは混ざる。
サイト別に見たいので、確認が通ったあとに「URLプレフィックス」で
`https://en.kokeniwa.net/` と `https://ja.kokeniwa.net/` も追加する。
親ドメインが確認済みなら、この2つは**確認作業なしで即通る**。

- ドメインプロパティ … 全体の俯瞰用
- URLプレフィックス2つ … 記事改稿に使う実務用。`fetch_seo.py` はこちらを見る

### サイトマップを送信

各プロパティの左メニュー「サイトマップ」で、そのサイトのものを送信する。

- `https://en.kokeniwa.net/sitemap.xml`（en のプロパティ）
- `https://ja.kokeniwa.net/sitemap.xml`（ja のプロパティ。kokeniwa-japanese 側）

## 2. GA4 を作る

1. https://analytics.google.com → 管理 → アカウント作成（例: Kokeniwa）
2. プロパティ作成（例: Kokeniwa English）→ データストリーム → **ウェブ** →
   `https://en.kokeniwa.net`
3. 表示される **測定ID**（`G-XXXXXXXXXX`）を `site_config.json` に入れる

```json
"analytics": {
  "ga4_measurement_id": "G-XXXXXXXXXX",
  "google_site_verification": ""
}
```

4. ビルドして `dist/` ごとコミット・プッシュ（＝デプロイ）

```
python site/build_site.py
```

タグは `location.hostname` が本番ホストのときだけ発火する。ローカルの
`python -m http.server` プレビューは計測に混ざらない。

5. GA4 管理画面 → 管理 → **Search Console のリンク** で 1 のプロパティと紐づけると、
   GA4側でも検索クエリ別のレポートが見られる。

プライバシーポリシー（`/privacy/`）はGA4の測定IDが入ると自動でCookie・オプトアウトの
記述に切り替わる（`site/templates/pages.py` の `render_privacy()`）。

---

## 3. サービスアカウントを作る（Claudeがレポートを読むため）

1. https://console.cloud.google.com → プロジェクトを作成（例: kokeniwa-seo）
2. 「APIとサービス」→「ライブラリ」で次の2つを **有効化**
   - Google Search Console API
   - Google Analytics Data API
3. 「IAMと管理」→「サービスアカウント」→ 作成（例: `seo-reader`）。ロールは不要。
4. 作ったサービスアカウント → 「キー」タブ → 鍵を追加 → **JSON** → ダウンロード
5. ダウンロードしたJSONを `.secrets/google-sa.json` に置く（`.gitignore` 済み）
6. サービスアカウントのメールアドレス（`seo-reader@....iam.gserviceaccount.com`）に権限を渡す
   - **Search Console**: 設定 → ユーザーと権限 → ユーザーを追加 → 権限「制限付き」
   - **GA4**: 管理 → プロパティのアクセス管理 → ＋ → 役割「閲覧者」
7. `.env` に次を追記（`.gitignore` 済み）

```
GSC_SITE_URL=https://en.kokeniwa.net/
GA4_PROPERTY_ID=123456789
```

- `GSC_SITE_URL`: URLプレフィックスなら `https://en.kokeniwa.net/`（末尾スラッシュまで
  正確に）。ドメインプロパティ全体を見るなら `sc-domain:kokeniwa.net`（en/ja 合算）。
- `GA4_PROPERTY_ID`: GA4 管理 → プロパティの詳細 に出る数字のID（`G-` の測定IDとは別物）。

## 4. レポートを取得する

```
pip install google-auth
python scripts/fetch_seo.py            # 直近28日
python scripts/fetch_seo.py --days 90
```

`reports/` に `seo_YYYY-MM-DD.md` / `.json` と、常に最新を指す `latest.md` が出る。

レポートの中身:

| セクション | 使いどころ |
|---|---|
| ページ別 / クエリ別 | 何が伸びているか |
| 表示は多いが順位が低いクエリ | 既存記事の加筆・見出し調整の候補 |
| 順位は高いがCTRが低いページ | タイトルとdescriptionの書き直し候補 |
| ブログ記事ごとの流入クエリ | その記事が実際に何で読まれているか |
| GA4 ページ別・流入チャネル | 滞在・回遊、SNS経由かオーガニックか |

Search Console のデータ確定には2〜3日かかるため、直近3日は集計から除いている。
GA4 は登録直後はデータが空。計測開始から数日待つこと。

---

## 5. Claude Code での使い方

取得したあとに、そのまま頼めばいい。

- 「`reports/latest.md` を読んで、改稿すべき記事とその理由を挙げて」
- 「表示が多いのに順位が低いクエリをもとに、新しい記事のテーマを3つ提案して」
- 「`/blog/accounting-english-basics/` の流入クエリを見て、記事に足りない見出しを補って」

Claude 側から先にレポートを更新させたいときは「`python scripts/fetch_seo.py` を実行して
最新を取ってから分析して」と言えば、実行から分析まで通してやる。

## 6. 姉妹サイト（kokeniwa-japanese）

同じ仕組みを ja.kokeniwa.net にも入れてある（`../kokeniwa-japanese/docs/セットアップ_解析連携.md`）。

使い回せるもの / 分けるもの:

| | 扱い |
|---|---|
| Google Cloud プロジェクト・サービスアカウント・JSON鍵 | **共通**。同じ鍵を ja 側の `.secrets/` にもコピーする |
| Search Console プロパティ | 分ける（URLプレフィックスを en / ja それぞれ） |
| GA4 プロパティ・測定ID | **分ける**。読者層も言語も別で、混ぜると解釈が濁る |
| 権限付与 | サービスアカウントのメールを ja 側のGSC・GA4にも追加する |

# 学習サイトのビルドと公開（Cloudflare Pages）

## 構成

- ソース: `site/`（ビルダー・テンプレート・CSS/JS）、`content/blog/*.md`（ブログ記事）、`site_config.json`（設定）
- データ: `data/reading_problems.jsonl`、`data/uscpa_words.csv`、`data/legal_words.csv`（投稿システムと共用。サイト側からは読み取りのみ）
- 出力: `dist/`（**コミット対象**。Cloudflare Pagesはこれをそのまま配信する）

## ビルド

```
python site/build_site.py
```

- 標準ライブラリのみで動く（追加インストール不要）
- `dist/` を毎回作り直し、全ページ生成後に内部リンク切れを検査する（切れがあれば exit 1）
- ローカル確認: `python -m http.server 8788 --directory dist` → http://localhost:8788

**データや記事を更新したら、ビルドして `dist/` ごとコミット・プッシュする。** これがデプロイになる。

### ブログ記事を追加したときにもう1つやること

```
python scripts/build_og_images.py blog-covers
```

記事ごとのカバー画像（一覧カードのサムネ＋その記事のOGP）を生成する。
`site/static/og/blog/{slug}.png` と `{slug}-card.webp` が出るので、これもコミットする。
Cloudflare は `dist/` を配信するだけでビルド時に Pillow を動かさないため、
生成物をリポジトリに入れておく必要がある。

回し忘れても一覧・記事ページは壊れず、共通のブログ画像に落ちる（サムネは非表示）。
気づいたときに回せばよい。

新しいトピックを使うときは `site/templates/blog.py` の `TOPICS` に1行足す。
アクセント色・アイコン・`/blog/topic/{slug}/` のアーカイブ・一覧の絞り込み導線が
まとめて増える。`TOPICS` に無い topic を front matter に書くと、
既定色で表示されアーカイブは作られない。

## 設定（site_config.json）

公開前に差し替えるプレースホルダ:

| キー | 内容 |
|---|---|
| `base_url` | 公開URL（例 `https://english-hub.pages.dev` または独自ドメイン）。sitemap・OGP・canonicalに使われる |
| `sns.*.handle` / `sns.*.url` | 3アカウントの@ユーザー名とThreads URL |
| `site_name` / `tagline` | サイト名（現在は仮の「English Hub」） |

`include_draft`: 読解問題の draft を載せるか（現在true。全問draftのため）。`rejected` は常に除外。

## コンテンツごとの方式（重要）

### 英文解釈（reading）
問題ごとに静的な個別ページ（`/reading/{id}/`）。SEO対象。SNS集客の主力。

### 語彙（vocab）— フラッシュカード一覧方式
`/vocab/uscpa/` `/vocab/legal/` は**各1枚**のページで、`site/static/vocab-trainer.js` が
`static/data/{set}.json` を読み、**科目内の全語をカードのグリッドで一覧表示**する。
各カードは表(英単語)⇄裏(意味)を**個別に反転**（タップ/クリック）。**データが増えてもページ数は一定。**

- `?subject=far` … 科目チップで切替
- `#w{id}` … **投稿連動**。その語の科目を開き、その語のカードへスクロール＆反転＆強調
- 「すべて意味を表示」ボタンで全カード一括反転

（補足: 語彙CSVは連続5idが必ず同一科目に収まる並びなので、投稿5語＝1科目。
`#w{先頭id}` で科目が確定し、その5語が近接して並ぶ。）

収益設計上の制約（意図的にこうしている）:
- **カード面は選択不可**（`user-select:none`。ページ全選択→コピーで単語帳を抽出させない）
- 初期は英単語だけ見え、意味はめくらないと出ない
- **例文はサイトに出さない**（`build_json` がJSONに含めない。Kindle版の価値に残す）
- フラッシュカードページは **noindex**（検索から単語一覧が丸見えになるのを防ぐ）。sitemapにも載らない
- 限界: `static/data/{set}.json` 自体は取得可能（term/meaningのみ）。casualなコピペ対策であり完全秘匿ではない

### 英単語トレーニング（training）— フラッシュカード一覧方式
旧 english-learner「こつこつ英単語」を統合したもの。一般英語の単語帳で、
`/training/` が入口（index可）、`/training/{slug}/` が各カード一覧本体（noindex）。
**USCPA/法律の語彙とUIを統一**し、`site/static/training-grid.js` が
`static/data/training-{slug}.json` を読み、全語をカードのグリッドで一覧表示する
（各カードは表(英単語)⇄裏(意味)を個別に反転。`.fc-*` のCSSを語彙と共用）。
※旧 english-learner の確認テスト・ディクテーションは移植していない（不要との判断）。

5カテゴリ: 英検準1級(eiken-pre1/1500)・ニュース(news/584)・ドラマ(drama/528)・
句動詞(phrasal/283)・イディオム(idioms/25)。元データは `data/training/*.jsonl`
（1行1語: `id/word/meaning/example/example_ja`。**このリポジトリで直接編集する**。
例文フィールドは持っているがサイトのJSONには出さない＝`build_json` は id/t/m のみ）。

- カードをタップで英単語⇄意味を個別反転、「すべて意味を表示」で一括反転
- `#w{id}` … **投稿連動**の受け皿。その語のカードへスクロール＆反転＆強調（語彙と同じ）

`japanese/`（英語話者向けの日本語学習）は統合対象外（別プロジェクトで扱う予定）。
SNSの実投稿スクリプトはまだ移行していない（`@english_vocabulary_kotsukotsu` は現状 english-learner 側で稼働）。

## 投稿との連動（受け皿は用意済み、URL投稿は未実装）

投稿本文にサイトURLを入れる処理はまだ `auto_post.py` / `format_*_post.py` に入れていない。
入れるときのURL形式は以下（`base_url` は `site_config.json` から取得）:

| 投稿 | 入れるURL |
|---|---|
| 英文解釈（1問=1スレッド、id=N） | `{base_url}/reading/{N}/` |
| 語彙（`【…No.1-5…】`の5語） | `{base_url}/vocab/uscpa/#w1`（先頭語のid。法律は `/vocab/legal/`） |
| 英単語トレーニング（こつこつ英単語） | `{base_url}/training/news/#w1`（先頭語のid。カテゴリはslug） |

サイト側は既にこれらのURLを正しく解釈する。投稿側に1行足すだけで連動が完成する。

## Kindle読者特典（`/kindle/` とCSVダウンロード）

`anki/*.csv`（Ankiインポート用）を `dist/downloads/` へビルド時にコピーする（トークンなし）。

### 動線: 本 → 特典ページ → CSV

**Kindle本にはCSVの直リンクを書かない。** 書籍ごとの特典ページのURLだけを記載し、
ダウンロードはそのページのボタンから行わせる。

| 書籍 | 本に記載するURL | 配布物 |
|---|---|---|
| 英文解釈トレーニング200問 | `{base_url}/kindle/reading/` | `reading_anki.csv` |
| USCPA頻出英単語1000 | `{base_url}/kindle/uscpa/` | `uscpa_anki.csv` |
| 英文契約書の頻出英単語380 | `{base_url}/kindle/legal/` | `legal_anki.csv` |

この形にしている理由:

1. **本を差し替えずに案内を更新できる。** Kindleは出版後に既存読者へ更新を届けられない。
   URLを固定し、中身（配布物・対応アプリ）はページ側で変える。
2. **告知チャネルになる。** データが欲しい人は必ずこのページを通るため、
   `pages.py` の `KINDLE_ANNOUNCEMENT` を埋めて再デプロイすれば全書籍の特典ページに同時掲示される
   （既定は `None` で非表示）。
3. **書籍ごとにデータを分離する。** 1ページ＝1ファイル。他書籍のデータへは導線を作らない。
   単語帳の**例文はサイトに出していない有料側の差別化要素**なので、
   読解本を1冊買った人がUSCPA・法律の例文を入手できる状態を避ける。

`/kindle/`（親）に直接来た人には「書籍記載のURLを開いてください」とだけ表示し、各データへは張らない。

### 配信設定

- `/kindle/*` は **noindex**（sitemapにも載せない）。書籍の読者だけが辿り着くページ
- `_headers` で `/downloads/*` に `X-Robots-Tag: noindex` と `Content-Disposition: attachment` を付与
- 認証はなく「URLを知れば誰でもDL可」。バレても許容という方針でこうしている
  （KDP規約上、特典の受け取りに個人情報の登録は要求できない。
  厳密な購入者限定が必要になれば Cloudflare Access 等が別途必要）
- ファイルを増減したいときは `anki/` に置いて再ビルドし、`pages.py` の `KINDLE_BONUS` に項目を足す

## Cloudflare Pages 初回セットアップ（ダッシュボード側・手動）

1. GitHubにこのリポジトリをプッシュ
2. Cloudflare ダッシュボード → Workers & Pages → Create → Pages → Connect to Git
3. このリポジトリを選択し、以下を設定:
   - **Build command**: （空欄のまま）
   - **Build output directory**: `dist`
4. デプロイ後に発行されるURL（`*.pages.dev`）を `site_config.json` の `base_url` に設定 → 再ビルド → コミット

以降は main へのプッシュで自動デプロイされる。

## ブログ記事の追加

`content/blog/スラッグ名.md` を作成。ファイル名がURL（`/blog/スラッグ名/`）になる。

```markdown
---
title: 記事タイトル
date: 2026-07-15
description: 一覧とmeta descriptionに使う要約
---

本文（見出し##・リスト・**強調**・`コード`・[リンク](/reading/)・> 引用 に対応）
```

- `draft: true` を front matter に書くと非公開
- 複雑なHTMLが必要な記事は `raw_html: true` を付けて本文をHTMLで書く

## 新カテゴリ・新科目を追加したら

- 読解問題の `category` を増やした場合: `site/lib/config.py` の `CATEGORY_SLUGS` にスラッグを追加（無いとビルドエラーで知らせてくれる）
- 語彙CSVの `subject` を増やした場合: 同ファイルの `USCPA_SUBJECTS` / `LEGAL_SUBJECTS` に追加
- 英単語トレーニングのカテゴリを増やす場合: `data/training/{名前}.jsonl` を置き、`config.py` の `TRAINING_SETS` に1項目追加

## english-learner の統合状況

english-learner の学習コンテンツは**このリポジトリに取り込み済み**（`/training/` として統合）。
元の `word_data/*.jsonl` は `data/training/` にコピーし、確認＋ディクテーション機能を
`training-trainer.js` として当サイトのデザインで再実装した。english-learner 自体はそのまま残している。

- **統合済み**: news / drama / phrasal / idioms / eiken_pre1（5カテゴリ・計2920語）
- **統合対象外**: `japanese/`（英語話者向けの日本語学習。別プロジェクトで移行予定）、
  affiliateのLP・おすすめリソースページ（当サイトの `/books/` を使う）
- **未移行**: SNSの実投稿スクリプト（`scripts/threads_post*.js`）。`@english_vocabulary_kotsukotsu`
  は当面 english-learner 側で稼働。将来こちらの [[threads-autopost]] 系に寄せる予定

URL名前空間は最初から `/training/` を含め衝突しない設計。
